01 README

Why build an OS?

I wanted a project where abstractions eventually run out. Axiom starts at the boot protocol and works upward through interrupts, memory, storage, processes, accounts, services, graphics, sound, and applications.

The goal is not to replace a daily-driver OS tomorrow. The goal is to keep making each layer real, understandable, and testable.

Project rules

  • 01 Build the core rather than hiding it behind a framework.
  • 02 Keep the source readable enough to learn from later.
  • 03 Test every boot milestone in BIOS and UEFI QEMU.
  • 04 Keep physical disks read-only until writes are trustworthy.
  • 05 Preserve a terminal recovery path as the desktop grows.

05 BUILD / RUN

Reproduce it locally.

The normal workflow uses Arch WSL. ./all checks dependencies, cleans old output, builds the freestanding kernel, and packages a hybrid ISO beside the README.

Heads up: use QEMU first. Axiom is hobby software and should not be trusted with important physical disks or data.

~/src/axiom
$ git clone -b stable https://github.com/Vvoidddd/Axiom.git
$ cd Axiom
$ ./all

Axiom build complete: axiom.iso
